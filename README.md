# mycomputer-figma-sync

Сторож между продакшеном академии «Мой компьютер» и макетами Figma. При выкатке собирает
слепок прода и готовит список правок для макетов.

**Направление одностороннее: прод — эталон.** Агент никогда не предлагает править код;
всё, что он находит, — это работа по макету.

## Что синхронизируется с чем

| Сеть / раздел | Эталон в коде | Файл Figma |
|---|---|---|
| mycomputer.education | `sites/main` | Мій Комп'ютер Едьюкейшн `zo7XvbI2c5FVdhnlCm9rgr` |
| mycomputer.school | `sites/design` | Май Компьютер Скулл `hGtcaSVjArhw8mFbRNNeHI` |
| админка / дашборд | `sites/main/admin.html` + `server/` | Дашборд май компьютер `wc5OsxDTfq4DzngB8wS9iw` |

Полная карта — в [config/design-map.json](config/design-map.json). Это единственное место,
где живёт связь «код → макет»: изменённые при деплое файлы прогоняются по `codePaths` таргета,
и так определяется, в каком файле Figma заводить страницу правок.

Имя `sites/design` обманчиво — это главная mycomputer.school, а не курс по дизайну.

## Запуск

Одинаково на macOS и Windows. Нужен Node 20+.

```
npm run snapshot     # собрать слепок токенов из кода прода
```

Путь к репозиторию продакшена берётся из `MC_REPO_PATH` (см. `.env.example`), иначе ищется
как `~/Projects/my-computer-new`. Можно передать явно: `npm run snapshot -- --repo <путь>`.

## Почему состояние лежит в git

`state/` коммитится намеренно. Пользователь работает с двух машин — MacBook и Windows-ноутбука,
и обе должны видеть одну картину. Побочная выгода: разницу между деплоями показывает обычный
`git diff`, отдельный детектор изменений не нужен.

**Слепки геометрии — единственное, что у каждой машины своё:** `state/layout/education.darwin.json`
и `education.win32.json`. Один и тот же прод в headless Chrome меряется по-разному — на маке шрифт
резолвится в `system-ui`, на Windows в `BlinkMacSystemFont`, метрики расходятся, и высота главной
отличается на 183 px при неизменном коде. В общем файле каждая смена машины выглядела бы как сотня
правок прода. `changes` берёт строго слепок своей машины, `vsfigma` и план правок соглашаются на
чужой, но говорят об этом вслух. Токены платформонезависимы и лежат в одном файле на всех.

## Ежедневная синхронизация машин

`sync/daily-sync.js` подтягивает свежую память, состояние агента и прод, снимает слепки и
отдаёт их второй машине. Ставится в планировщик своей ОС — launchd на маке, Task Scheduler
на Windows:

```
node sync/install-schedule.js        # поставить задачу на 10:00
node sync/install-schedule.js --at 21:30
node sync/install-schedule.js --full # снимать ещё страницы сайтов и 60 экранов админки
node sync/install-schedule.js --off  # снять
```

Порядок шагов внутри прогона не случаен: прод подтягивается **до** снятия слепков, иначе
слепок токенов снимется со вчерашнего кода, а коммит и отправка идут **после**, иначе свежие
слепки пролежали бы на машине до следующего дня. Каждый слепок независим: упавший (нет
браузера, нет ключа админки) пишет причину в лог и не роняет остальные.

По умолчанию снимаются токены и геометрия трёх главных — это около трёх минут. Страницы
сайтов и экраны админки добавляет `--full`, они дают ещё минут двенадцать. Отключить снятие
целиком: `node sync/daily-sync.js --no-snapshots`.

Лог — `sync/daily-sync.log`, пишется в UTF-8 с BOM: без BOM PowerShell 5.1 и Блокнот читают
его как ANSI и показывают кракозябры вместо русского.

## Устройство

| Файл | Что делает |
|---|---|
| `src/snapshot/tokens.js` | разбирает `:root` в CSS сайта, раскрывает `var()`, раскладывает по категориям |
| `src/snapshot/rules.js` | отделяет тему курса от дрейфа, ловит рассинхрон hex и rgb-двойника |
| `src/cli.js` | точка входа |
| `config/design-map.json` | карта «код → макет» |

Никаких зависимостей, никаких shell-скриптов, пути только через `path.join` — чтобы одинаково
работало на обеих машинах.
